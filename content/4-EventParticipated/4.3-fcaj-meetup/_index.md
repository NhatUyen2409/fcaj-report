<h2 class="report-section-title">I. Event Overview</h2>
</div>
<div class="report-prose">
<p>The <strong>First Cloud AI Journey Meetup</strong> focused on five core technical domains: <strong>Voice AI</strong>, <strong>AWS Resource Access Manager (RAM)</strong>, <strong>AI-assisted Penetration Testing</strong>, <strong>Amazon Bedrock AgentCore</strong>, and <strong>Kiro Crew</strong>.</p>

<div style="background: #f8fafc; border: 1px solid #e2e8f0; border-left: 4px solid #f97316; border-radius: 6px; padding: 12px 16px; margin: 16px 0;">

<strong>Featured Speakers:</strong> <strong>Kiệt Trần, Long Huỳnh, Thịnh Nguyễn, Xuân An, Khoa Kiều, Nghi Danh</strong>
</p>
</div>

<div class="report-quote-box" style="border-left-color: #171717;">
“The meetup gathered technology leaders, solutions engineers, and the AWS community in Vietnam, presenting technical lectures, live architecture demonstrations, and discussions on practical cloud and artificial intelligence applications in enterprise environments.”

<p>The technical scope spanned real-time low-latency voice AI systems, secure cross-account cloud resource sharing, Shift-Left automated penetration testing, and production runtime environments and memory management for AI Agents.</p>

<h2 class="report-section-title">III. Event Content & Technical Sessions</h2>
</div>
<div class="report-prose">

<!-- 1. Voice AI Contact Center -->
<h3 style="font-size:16px; font-weight:800; color:#0F172A; margin:24px 0 10px 0;">1. Hear, Think, Speak – Building a Vietnamese Voice-AI Contact Center on AWS</h3>
<p style="font-size:14px; color:#555555; margin-bottom:12px;">
<strong>Speaker:</strong> Kiệt Trần – Revve AI
</p>
<p>The session focused on three primary criteria in engineering production Voice AI systems: <strong>Response Accuracy</strong>, <strong>Low Latency</strong>, and <strong>Natural Conversational Experience</strong>.</p>
<p>The live demonstration showcased an AI-powered voice interview screening Cloud Engineer candidates in Vietnamese, engineered to reduce end-to-end response latency to approximately <strong>1.8 seconds</strong> for smooth conversational turn-taking.</p>

<h4 style="font-size:14.5px; font-weight:700; color:#171717; margin:18px 0 8px 0;">Voice AI Processing Workflow</h4>
<div class="minimal-formula-box" style="text-align: center; font-weight: 600; overflow-x: auto;">
Voice Input → Speech Recognition → AI Processing → Speech Generation → Voice Response
</div>

<!-- 2. AWS Resource Access Manager (AWS RAM) -->
<h3 style="font-size:16px; font-weight:800; color:#0F172A; margin:24px 0 10px 0;">2. AWS Resource Access Manager (AWS RAM)</h3>
<p style="font-size:14px; color:#555555; margin-bottom:12px;">
<strong>Speaker:</strong> Long Huỳnh – Styl Solution
</p>
<p>The second session addressed secure cross-account resource sharing across multiple AWS accounts within an enterprise organization.</p>
<p>AWS Resource Access Manager allows supported resources (VPC Subnets, Transit Gateways, Route 53 Resolver Rules) to be shared without requiring duplicated infrastructure across sub-accounts, reducing overhead and streamlining centralized management.</p>

<h4 style="font-size:14.5px; font-weight:700; color:#171717; margin:18px 0 8px 0;">Key Components</h4>
<div class="minimal-table-wrap">

<!-- 3. AWS Pentest with AWS Continuum / Security Agent -->
<h3 style="font-size:16px; font-weight:800; color:#0F172A; margin:24px 0 10px 0;">3. AWS Pentest with AWS Continuum / Security Agent</h3>
<p style="font-size:14px; color:#555555; margin-bottom:12px;">
<strong>Speaker:</strong> Thịnh Nguyễn – Styl Solution
</p>
<p>The third session introduced automated infrastructure security assessment and penetration testing assisted by AI Security Agents, emphasizing early vulnerability identification during the software development lifecycle (SDLC).</p>

<h4 style="font-size:14.5px; font-weight:700; color:#171717; margin:18px 0 8px 0;">Shift-Left Security</h4>
<p>The Shift-Left Security methodology was outlined through four progressive validation checkpoints:</p>
<ul>
<li>Reviewing Terraform infrastructure-as-code (IaC) definitions.</li>
<li>Integrating automated security checks into GitHub and GitLab pull requests.</li>
<li>Pinpointing misconfigurations and security exposures prior to deployment.</li>
<li>Deploying AI Security Agents to execute automated penetration tests in authorized SIT and UAT environments.</li>
</ul>

<h4 style="font-size:14.5px; font-weight:700; color:#171717; margin:18px 0 8px 0;">Security Assessment Workflow</h4>
<div class="minimal-formula-box" style="text-align: center; font-weight: 600; overflow-x: auto;">
Source Code → Security Review → Testing Environment → Security Validation → Production Deployment
</div>

<hr style="border:0; border-top:1px solid #E5E5E5; margin:32px 0;" />

<!-- 4. Amazon Bedrock AgentCore -->
<h3 style="font-size:16px; font-weight:800; color:#0F172A; margin:24px 0 10px 0;">4. Amazon Bedrock AgentCore</h3>
<p style="font-size:14px; color:#555555; margin-bottom:12px;">
<strong>Speaker:</strong> Xuân An – Leader AWS Student Builder Group HCMUTE
</p>
<p>The session focused on two primary architectural components of Amazon Bedrock AgentCore: <strong>AgentCore Runtime</strong> and <strong>AgentCore Memory</strong>.</p>
<p>Associated technical topics addressed execution environments, context management, scalability, and operating AI Agents within production workloads.</p>

<h4 style="font-size:14.5px; font-weight:700; color:#171717; margin:18px 0 8px 0;">4.1. AgentCore Runtime</h4>
<p>AgentCore Runtime provides a managed execution environment for deploying and operating AI Agents. Key architectural factors include:</p>
<ul>
<li>Agent execution and workload isolation.</li>
<li>Elastic infrastructure scalability matching demand.</li>
<li>Optimized compute resource utilization.</li>
<li>Enterprise production deployment requirements.</li>
</ul>

<h4 style="font-size:14.5px; font-weight:700; color:#171717; margin:18px 0 8px 0;">4.2. AgentCore Memory</h4>
<p>AgentCore Memory manages conversational context and persistent interaction states across multi-turn AI Agent workflows.</p>

<!-- 5. Kiro Crew -->
<h3 style="font-size:16px; font-weight:800; color:#0F172A; margin:24px 0 10px 0;">5. Kiro Crew – AI-Powered Development and Automation</h3>
<p style="font-size:14px; color:#555555; margin-bottom:12px;">
<strong>Speakers:</strong> Khoa Kiều – Tech Lead, ACB &amp; Nghi Danh – AWS Community Builder
</p>
<p>The final session explored how autonomous AI Agent groups support continuous software development, automated code inspection, and system status monitoring.</p>

<h4 style="font-size:14.5px; font-weight:700; color:#171717; margin:18px 0 8px 0;">5.1. Artifact Generation</h4>
<p>The live demonstration showed AI Agents collecting real-world job postings, parsing data streams, and generating interactive visual reports and analytical charts directly within the workspace.</p>

<h4 style="font-size:14.5px; font-weight:700; color:#171717; margin:18px 0 8px 0;">5.2. Context Window Management</h4>
<p>The speakers analyzed context window optimization techniques for long-running workflows via two core mechanisms:</p>
<ul>
<li><strong>Auto Compact:</strong> Automatically condenses conversation context as token usage approaches context limits.</li>
<li><strong>Context Breakdown:</strong> Analyzes token distribution across components to isolate context expansion factors.</li>
</ul>

<h4 style="font-size:14.5px; font-weight:700; color:#171717; margin:18px 0 8px 0;">5.3. Memory Management &amp; Security Guardrails</h4>
<p>The presentation emphasized selective memory retention and establishing strict security guardrails preventing AI Agents from:</p>
<ul>
<li>Deleting cloud infrastructure without explicit authorization.</li>
<li>Exposing sensitive secrets, access keys, or API credentials.</li>
<li>Performing unauthorized system or configuration modifications.</li>
<li>Executing destructive or high-risk operations without human oversight.</li>
</ul>
